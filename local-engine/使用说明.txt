Galaxy Local Engine 使用说明（Windows）
======================================

用途
----
Galaxy Local Engine 用于在本机调用 yt-dlp + FFmpeg 下载和合并视频。
适合 YouTube、B站、小红书、快手、Dailymotion 等存在登录、反爬或 IP 绑定限制的平台。
视频、Cookie 和 FFmpeg 处理都留在本机，不上传 Galaxy 服务器。

0.15.0 主要变化
---------------
1. 正在下载的媒体任务新增“暂停当前”。暂停会安全停止下载 worker，并保留可续传的 `.part` / 分片临时文件。
2. 暂停后的任务会出现在任务中心“暂停 / 中断”范围，可选择继续或放弃恢复。
3. 退出 Galaxy Local Engine、程序异常中断或电脑重启后，未完成任务会在下次启动时显示为“中断”，不会自动开始下载，必须由你主动继续。
4. 普通 yt-dlp 任务会从源站允许的最近检查点继续；如果某个平台不支持可靠断点续传，界面会明确显示“重新开始”，不会假装从原百分比继续。
5. 暂停当前任务时等待队列不会抢先启动下一项；继续、放弃恢复或暂停过程中取消后，会恢复暂停前的队列状态。
6. 网站和桌面任务中心都可以查看可恢复任务；网站只看到脱敏后的任务摘要，完整链接和任务参数只保存在本机。

0.14.0 主要变化
---------------
1. 新增统一“任务中心”：当前下载、等待队列、完成历史、失败历史和取消任务放在一个窗口管理。
2. 任务中心支持搜索、状态筛选、队列暂停/继续、上移/下移、批量移到顶部和移除等待任务。
3. 失败任务自动分类并给出处理建议，例如网络异常、429 限流、浏览器 Cookie、登录验证、磁盘、区域限制、FFmpeg 和解析器问题。
4. 新增“智能重试”：只对网络、429 限流和未知瞬态失败自动调整本任务参数。
5. 智能重试参数只作用于这一项任务，不修改工作台全局设置，也不会影响其他排队任务。
6. 下载历史中的失败详情进一步脱敏：URL 凭据、query、fragment、token、authorization、cookie、session、password、secret 不写入历史。

重要安装方式
------------
1. Galaxy Local Engine 采用“便携式原地安装”。
2. 程序直接安装在你解压 GalaxyLocalEngine-Windows.zip 的文件夹，不再复制到 AppData。
3. FFmpeg、ffprobe 和 yt-dlp.exe 已经内置在压缩包里。
4. 双击 install.cmd 时不需要再访问 GitHub，也不需要另外下载 FFmpeg / yt-dlp。
5. 下载的视频默认保存在解压目录中的 downloads 文件夹。
6. 正常下载默认不会联网更新 yt-dlp；安装包发布时已经打包经过校验的版本。
7. 即使网站选择了 Edge / Chrome / Firefox 登录状态，本地引擎也会先尝试无需 Cookie 的公开下载；只有公开方式失败时才读取浏览器 Cookie。

一、首次安装
------------
1. 从 Galaxy Downloader 网站点击“下载 Galaxy Local Engine（官网线路）”。
2. 下载 GalaxyLocalEngine-Windows.zip。
3. 右键 ZIP → “全部解压”。不要直接在压缩包里面运行程序。
4. 建议把解压后的整个文件夹放到一个长期不移动的位置，例如 D:\GalaxyLocalEngine-Windows。
5. 打开解压后的文件夹，双击 install.cmd。
6. 安装器会自动：
   - 使用当前解压文件夹作为程序目录；
   - 检查内置的 FFmpeg / ffprobe；
   - 检查内置的 yt-dlp.exe；
   - 注册 galaxy-downloader:// 协议；
   - 创建 downloads 下载目录；
   - 自动关闭正在运行的旧版 Galaxy Local Engine；
   - 启动新版 Galaxy Local Engine。
7. 安装完成后，Galaxy Local Engine 窗口顶部会显示当前版本号。

程序位置：
当前解压文件夹

下载位置：
当前解压文件夹\downloads

示例：
D:\GalaxyLocalEngine-Windows\GalaxyLocalEngine.exe
D:\GalaxyLocalEngine-Windows\yt-dlp.exe
D:\GalaxyLocalEngine-Windows\ffmpeg\bin\ffmpeg.exe
D:\GalaxyLocalEngine-Windows\downloads\

二、在网站中使用
----------------
1. 在 Galaxy Downloader 网站解析视频。
2. 在“当前成品方案”中选择画质、音质、字幕和封面。
3. 保持 Galaxy Local Engine 正在运行。
4. 网站会自动检测本地引擎，正常状态应显示“本地引擎已连接”。
5. 登录状态建议：
   - 公开视频：可以选择“不读取浏览器 Cookie”；
   - 需要登录、年龄验证、账号权限的视频：选择已经登录目标网站的 Edge / Chrome / Firefox。
6. 点击“按当前方案本机下载”。
7. 如果选择了浏览器登录状态，本地引擎会先尝试无需 Cookie 的公开下载；只有失败后才读取浏览器 Cookie。
8. 网站与 Galaxy Local Engine 会同步显示下载状态和进度。
9. 下载完成后可点击“打开下载文件夹”。

三、任务中心怎么用
------------------
主窗口的“任务”按钮会打开任务中心。

任务中心可以同时看到：
- 当前：正在下载的任务和实时进度；
- 等待：排队任务及当前顺序；
- 完成：已经下载成功的历史；
- 失败：失败原因和恢复建议；
- 取消：用户主动取消的历史；
- 暂停 / 中断：可以继续或放弃恢复的未完成媒体任务。

常用操作：
- 搜索：按来源、文件名、错误文本、画质搜索；
- 范围：只看当前 / 等待 / 完成 / 失败 / 取消；
- 当前任务：暂停当前下载；
- 队列：暂停、继续、上移、下移、移到顶部、批量移除；
- 可恢复任务：继续 / 重新开始，或放弃恢复；
- 完成任务：打开文件、定位文件；
- 失败任务：原参数重试或智能重试。

四、智能重试怎么判断
--------------------
智能重试只处理适合自动改变传输参数的失败：

1. 网络超时 / 连接重置 / 临时 5xx：
   - 使用“弱网增强”；
   - 并发分片降到 2；
   - 不主动限速。

2. HTTP 429 / 明确源站限流：
   - 使用“弱网增强”；
   - 并发分片降到 1；
   - 速度限制为 5 Mbps。

3. 未知瞬态失败：
   - 使用“弱网增强”；
   - 并发分片降到 2。

以下情况不会盲目智能重试：
- 需要登录 / 验证码；
- 浏览器 Cookie 数据库被占用或解密失败；
- 磁盘空间不足；
- 区域限制；
- 内容删除 / 下架 / 权限限制；
- FFmpeg 后处理失败；
- 解析器失效 / 源站接口变化；
- 403 拒绝访问。

这类失败会先显示处理建议，处理原因后再点“原参数重试”。

五、浏览器 Cookie 被占用怎么办
------------------------------
Chrome、Edge 等 Chromium 浏览器在运行时可能锁定 Cookie 数据库。

新版处理方式：
1. 先自动尝试不读取 Cookie；公开视频通常可以直接成功；
2. 只有公开视频方式失败时，才读取你选择的浏览器登录状态；
3. 如果确实需要 Cookie，但浏览器数据库被占用，任务中心会把失败分类为“浏览器 Cookie 不可用”。

如果仍提示 Cookie 无法读取：
1. 确认目标网站已经在对应浏览器中登录；
2. 完全退出该浏览器，包括所有窗口和后台进程，然后重试；
3. 如果下载的是公开视频，网站登录状态改成“不读取浏览器 Cookie”即可。

六、网络与重试设置
------------------
工作台设置提供：
- 标准：10 次下载重试 / 10 次分片重试 / 5 次 extractor 重试；
- 弱网增强：20 / 20 / 8；
- 快速失败：5 / 5 / 3。

并发分片：1 / 2 / 4 / 8 / 16。
速度上限：不限速 / 1 / 2 / 5 / 10 / 20 / 50 / 100 Mbps。

默认仍是：标准 + 4 分片 + 不限速。
智能重试不会永久修改这些全局设置。

七、诊断日志与隐私
------------------
诊断日志默认关闭，可在工作台设置中主动开启。

日志位置：
当前解压文件夹\state\engine.log

日志会自动移除：
- URL 用户名 / 密码；
- query 参数；
- fragment；
- token；
- authorization；
- cookie；
- session；
- password / secret。

0.14 起，下载历史中的失败详情也使用同样的脱敏原则。

八、升级
--------
1. 再次点击网站上的“下载 / 更新 Galaxy Local Engine”。
2. 下载最新版 ZIP。
3. 完整解压到你想长期保留的位置。
4. 双击新版 install.cmd。
5. 安装器会自动关闭正在运行的旧版，并重新注册当前文件夹中的新版程序。
6. 返回网站，确认显示新版本号和“本地引擎已连接”。

如果你把整个 Galaxy Local Engine 文件夹移动到了其他磁盘或目录：
只需要在新位置重新双击一次 install.cmd，Windows 协议路径会自动刷新。

九、官网线路与 GitHub 备用线路
----------------------------
网站优先提供“官网线路”下载，并精确绑定网站当前要求的 Local Engine 版本。
如果官网线路临时不可用，页面同时保留同版本 GitHub Release 作为备用下载线路。

十、如果网站显示“本地引擎未连接”
--------------------------------
请依次检查：
1. Galaxy Local Engine 是否正在运行。
2. 是否安装的是网站要求的当前版本；旧版会被识别为不兼容，不会继续接收新任务。
3. 是否完整解压 ZIP 后运行了 install.cmd。
4. 是否在安装后移动过整个程序文件夹；如果移动过，请重新运行 install.cmd。
5. 刷新 Galaxy Downloader 网站。
6. 在浏览器地址栏打开：
   http://127.0.0.1:17836/health

如果能看到 JSON 状态，说明本地引擎通信服务已经启动。
如果打不开，请重新运行 install.cmd 或重新启动 Galaxy Local Engine。

十一、常见问题
--------------
Q：需要管理员权限吗？
A：通常不需要。程序直接使用当前解压目录，只注册当前 Windows 用户的协议。

Q：为什么一定要完整解压？
A：新版已经把 FFmpeg、yt-dlp 和安装脚本全部放在 ZIP 中。缺少任何文件都会导致安装校验失败。

Q：双击 install.cmd 时还会去 GitHub 下载 FFmpeg 或 yt-dlp 吗？
A：不会。安装所需组件已经全部内置。

Q：正常下载前会不会再去 GitHub 更新 yt-dlp？
A：默认不会。这样无法访问 GitHub 的电脑不会因为更新检查而卡住。新的 yt-dlp 会随新版 Galaxy Local Engine 一起发布。

Q：智能重试会不会把我的全局下载设置改掉？
A：不会。智能重试的网络参数只绑定到那一项任务。

Q：智能重试为什么有时不能点？
A：登录、Cookie、磁盘、区域限制、内容下架、解析器失效等问题需要先处理原因，重复自动请求没有意义。

Q：下载历史会不会保存账号 token？
A：不会主动保存未知 query。失败详情还会清理 URL 凭据、query、fragment 和常见 token/cookie/session 字段。

Q：本地引擎打开后显示 Waiting for a download job 正常吗？
A：正常。表示本地引擎已经启动并正在等待网站发送任务。

Q：下载文件在哪里？
A：解压文件夹里的 downloads 目录。

Q：可以移动整个程序文件夹吗？
A：可以。移动后在新位置重新运行一次 install.cmd 即可。

十二、卸载
----------
双击 uninstall.cmd 会移除 Windows 的 galaxy-downloader:// 协议注册。
程序文件和已经下载的视频仍保留在当前文件夹中；不再需要时直接删除整个文件夹即可。
